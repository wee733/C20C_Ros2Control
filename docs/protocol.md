# 协议依据与实现约定

## 来源

1. [先飞 C-20D 卧式产品页](https://www.allxianfei.com/c-20d-horizontal.html)。
2. [云台私有协议-XF(A5)V1.0.4](https://download.s21i.co99.net/22859939/0/4/ABUIABA9GAAg8pe11AYonvfA-wI.pdf)，文档日期 2026-07-23。协议版本 V1.0，注明适用固件 3.5 及以上。
   SHA-256：`5e0d736c069a00b4093797cfb092b4a092a2af111719ef6570a075e2ea527f0a`。
3. [C20D 卧式用户手册 V1.5](https://download.s21i.co99.net/22859939/0/4/ABUIABA9GAAgs5e11AYomNuWuwE.pdf)。
   SHA-256：`294a4918733dc0baa662d518c27c629bb0318b2b9531fa691ffd7cf610896bbe`。
4. [Tsuki808/Underwater-FPV-Gimbal](https://github.com/Tsuki808/Underwater-FPV-Gimbal)，MIT。用于研究已有串口实现思路；本驱动独立编写，字段按厂家手册和实机验证实现。参考项目的位布局与本版手册存在差异，没有照搬其打包方式。

多字节整数和 IEEE-754 float32 使用 little-endian，CRC 两字节为 big-endian。CRC 参数：poly `0x1021`、init `0x0000`、不反射、xorout `0x0000`，即 CRC-16/XMODEM 参数（不采用 X25 的反射与初值）。CRC 覆盖除末尾 CRC 两字节外的整帧。

## 主机到云台：40 字节

下表为原始线协议单位；ROS 自定义消息角度使用度、角速度使用度/秒（标准 JointState 仍为弧度），库编码接口则使用原始定点值。偏移从 0 开始。

| 字节 | 含义 |
| --- | --- |
| 0–1 | `A9 5B` |
| 2 | bits 7:3 指令码；2:0 重复指令触发计数 |
| 3 | bits 7:3 有符号 5 bit FPV 灵敏度（-16..15） |
| 4 / 7 / 10 | 横滚 / 俯仰 / 航向控制字：bit 3 回中翻转，5:4 模式，7:6 操作类型 |
| 5–6 / 8–9 / 11–12 | 对应 int16 目标，角度 0.01°、速度 0.1°/s |
| 13 | bit 7 载体惯导有效 |
| 14–19 | 载体 roll/pitch/yaw，int16 × 0.01° |
| 20–25 | 载体 north/east/up 加速度，int16 × 0.01 m/s² |
| 26–29 | bits 6:0 垂直 FOV 整数度；30:7 变倍 × 0.001 |
| 30–33 | float32 水平目标偏角，度，右为正 |
| 34–37 | float32 垂直目标偏角，度，下为正 |
| 38–39 | CRC 高字节、低字节 |

模式 0 FOLLOW、1 LOCK、2 FPV。手册明确横滚/俯仰不可使用 FOLLOW；任意轴使用 FPV 时所有轴都必须为 FPV，只支持角度。操作类型 0 角度、1 比例速度、2 真实速度。卧式 C20D 只提供两轴运动命令，保留三轴协议字段。

发送周期默认 10 ms。运动模式切换发指令码 4，收到对应指令回应后清零指令码，持续刷新控制字段；重复服务指令递增 3 bit 触发值。回应表示收到指令，不保证设备执行成功，状态透传至 ROS。

比例速度使用厂家 FOV/倍率换算语义，需要外部新鲜且非零的相机信息；驱动不猜测相机参数。点动/目标跟踪需要外部目标偏角，算法仍由云台及用户视觉系统完成。

## 云台到主机：26 字节

| 字节 | 含义 |
| --- | --- |
| 0–1 | `B5 9A` |
| 2 | 固件版本原始字节 |
| 3 | 硬件错误原始字节 |
| 4 | bit 0 立装；3:1 状态；bit 4 温度就绪 |
| 5 | bits 2:0 指令状态；7:3 指令码 |
| 6–11 | 相机角速度 **pitch/roll/yaw**，int16 × 0.1°/s |
| 12–17 | 相机姿态 **roll/pitch/yaw**，int16 × 0.01° |
| 18–23 | 相对角 **pitch/roll/yaw**，int16 × 0.01° |
| 24–25 | CRC 高字节、低字节 |

云台状态：0 未定义、1 初始化、2 停止、3 倾角保护、4 手动、5 点动，其余值原样发布。指令状态：0 执行中、1 成功、2 失败，其余原样保留。

`GimbalState` 中三组 `*_raw_*` 使用上述线序和定点值；三组换算数组统一为 roll/pitch/yaw，角度为度、角速度为度/秒。有效反馈才产生新消息，时间戳是主机接收时间，协议没有设备时间。解析器处理分片、粘包、噪声和 CRC 错误，坏帧不作为新鲜反馈。

## 文档与实机差异

- 附录 4 示例 3 状态字节 `0x19` 的 bit 0 为 1，与示例表中的吊装说明冲突。实现遵循位定义：1 立装，0 吊装。
- 厂家附录 2 的相机姿态定义含轴映射和 90° 偏置，不能直接当 ROS ENU 欧拉角。驱动公开厂家数据，不自动构造姿态四元数。
- 本次实机 FPV 原始俯仰指令与相对反馈异号，而 LOCK 俯仰指令与相机姿态反馈同号。ROS 层单独设置 FPV 俯仰符号参数；协议库不做这项修改，因此仍可逐字节匹配官方示例。
- 参考实现中指令码/触发位和轴模式位的位置与本版官方定义不同。测试直接使用官方附录报文（含 CRC）作为固定样本，并用独立 Python CRC 对节点发包进行交叉验证。
